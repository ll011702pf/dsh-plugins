# dsh-flowboard — frozen interface contract & product spec

Owned by the Lead. Writers must not edit this file. Every identifier below is frozen:
the bundle half, the client half, the template library and the verifier all build against
exactly these values.

Product: a **diagram / whiteboard studio** in the Harness Web sidebar for flowcharts,
architecture diagrams, user-journey maps, swimlanes, org charts and runbooks — with a
built-in template library, pan/zoom canvas, node & connector editing, and JSON / SVG /
Markdown export.

## 5. Document model (frozen)

```js
doc   = { version: 1, boards: [board, ...], activeId: string }
board = { id: string, name: string, nodes: [node, ...], edges: [edge, ...], view: { x, y, k } }
node  = { id, type, x, y, w, h, text, tone }
edge  = { id, from, fromPort, to, toPort, label, router, style, arrow, tone }
```

- `node.type` ∈ `NODE_TYPES` below. Unknown types degrade to `step`.
- `node.x` / `node.y` are top-left canvas coordinates in px; `w` / `h` are px.
- `node.text` is the resolved display string (already localized at insertion time).
- `node.tone` ∈ `TONES` below; unknown tones degrade to `default`.
- `edge.from` / `edge.to` are node ids inside the same board.
- `edge.fromPort` / `edge.toPort` ∈ `t | r | b | l`.
- `edge.router` ∈ `smooth | elbow` (default `smooth`).
- `edge.style` ∈ `solid | dashed` (default `solid`).
- `edge.arrow` ∈ `end | both | none` (default `end`).
- `edge.label` is `''` when the connector has no label.
- `board.view` is the pan/zoom camera `{ x, y, k }`; `k` is clamped to `[0.2, 2.5]`.
- Any malformed persisted payload must degrade to a fresh document instead of throwing.

### NODE_TYPES (frozen, in palette order)

This is a general drawing surface, not only a flowchart editor, so the generic
primitives come first in the palette. Each entry names the palette `group` it is
rendered under.

| type | default w × h | group | glyph intent |
| --- | --- | --- | --- |
| `rect` | 140 × 80 | draw | plain rectangle, any use |
| `ellipse` | 132 × 92 | draw | ellipse / cloud / circle |
| `triangle` | 132 × 100 | draw | triangle / pointer |
| `text` | 160 × 40 | draw | bare type, no outline |
| `line` | 140 × 4 | connect | horizontal rule |
| `arrow` | 140 × 4 | connect | rule with a filled head |
| `stroke` | freehand | draw | freehand pen: drag to draw |
| `highlighter` | freehand | draw | translucent thick highlighter |
| `eraser` | — | draw | rubs out freehand strokes |
| `terminator` | 136 × 48 | diagram | start / end pill |
| `step` | 148 × 56 | diagram | process rectangle |
| `decision` | 152 × 92 | diagram | diamond |
| `data` | 152 × 56 | diagram | parallelogram (input/output) |
| `document` | 148 × 62 | diagram | document with folded bottom edge |
| `note` | 168 × 84 | diagram | annotation, folded corner, dashed |
| `actor` | 156 × 52 | diagram | person |
| `service` | 160 × 56 | diagram | service / component |
| `database` | 148 × 72 | diagram | cylinder |
| `band` | 420 × 150 | diagram | labelled region: swimlane, layer, or journey row |
| `frame` | 460 × 320 | layout | section frame with a title band |
| `table` | 360 × 180 | layout | grid with a header row |

`text` renders with no outline and no fill; `line`, `arrow` and `stroke` render as open
strokes with no fill. All four are ordinary nodes for selection, movement, resizing,
connectors and export.

`sticky` is a paper note: a solid light stock colour per tone (`STICKY_PAPER`), no outline,
fixed dark ink `#2a2c31`, and text laid out from the top-left rather than centred.

`stroke`, `highlighter` and `eraser` are the three **drawing modes** rather than placed
shapes: their palette buttons arm a mode, and the button shows an armed state while active.
`highlighter` and `eraser` never appear in the document as node types — a highlighter stroke
is a `stroke` node carrying `ink: 'highlighter'`, and the eraser creates no node at all.

`stroke` is special: the palette button **arms a pen mode** rather than placing a shape.
While armed, a drag anywhere on the canvas records the path the pointer travels into
`node.points` (node-local coordinates, sampled at ≥ 2px intervals, capped at 3000 points).
The stroke is rendered as a smoothed quadratic path through those points, so each drawing
is a real freehand line rather than a fixed shape. A click without movement creates
nothing, and `Esc` disarms the pen. A stroke node's own `w` / `h` are derived from the
extent of its points.

`band` nodes always render behind every other node type, in array order.

`node.points` is present **only** on a freehand `stroke`; every other node omits the key
entirely so a document serializes identically whether it came from a template, a fresh
node, or storage. `node.ink` is likewise present only on a `stroke`, and is `pen` or
`highlighter`.

### Containers: `frame` and `table`

`frame` carries its title in `node.text`, rendered left-aligned and bold in a header band
across its top edge. It is grabbable **by that header band only**: its interior passes
clicks through to the shapes placed inside it, so content stays reachable. Adding a shape
while a frame is selected drops it inside that frame.

`table` carries a grid in `node.table = { cols, rows, cells }`, where `cells` is row-major
`string[][]`. Row 0 is rendered as a header row (bold, primary ink); later rows use
secondary ink. `cols` and `rows` are clamped to `1..12`. Malformed grids degrade to a
blank 3 × 2 table. The in-panel editor edits cells one at a time and can grow or shrink
either axis, preserving whatever cells remain.

Neither a frame nor a table is discarded when its editor is cancelled with no text: their
content lives elsewhere (a title band, or the cells).

Double-click behaviour is part of the contract:

- `table` — double-click **never** opens the single-text editor, because that editor writes
  `node.text` and a table renders only its cells; typing there would be silently lost.
  It selects the table instead, which shows the cell grid in the inspector. A legacy
  `node.text` left by an older build is rendered in the header row so nothing is hidden.
- `frame` — double-click opens the title editor **only inside the header band**. Double-
  clicking the body just selects the frame, so the interior never looks editable.

### Paint order (frozen)

Bands first, then frames, then highlighter strokes, then everything else. A highlighter must never
cover the text it marks, and a band must never cover a highlight. Connectors paint after
all nodes.

### Selection model

`selectedIds` is a list of node and edge ids. Marquee (Shift-drag on empty canvas) and
Shift-click both modify it. Resize grips appear only when exactly one node is selected.
Dragging any member of a group moves the whole group as one undo step.

### TONES (frozen ids and artwork colours)

```js
TONES = {
  default: null,       // no tint: theme tokens only
  blue:   '#3d7bb8',
  teal:   '#2f8f8f',
  green:  '#2f8a52',
  amber:  '#c9772f',
  rose:   '#b3543f',
  violet: '#8a5fb0',
  slate:  '#6b6f7d',
}
```

These eight hex values are the panel's artwork and are the only literal colours allowed.
Every other surface, border, label and control must use `--dsw-alias-*` theme tokens.
Shapes take `--fb-accent` / `--fb-fill` custom properties, which the tone maps onto
theme tokens for `default` and onto `color-mix(... var(--dsw-alias-bg-layer-1))` otherwise.

## 6. Template library (frozen contract)

`src/templates.data.js` is a **bare array expression** (no `const`, no trailing
semicolon needed) appended directly after `const TEMPLATES =` in the built module.

```js
[
  {
    key: 'flowchart',                       // frozen, also the locale key suffix
    nodes: [
      { id: 'n1', type: 'terminator', x: 96, y: 40, tone: 'green',
        zh: '提交请假', en: 'Submit request' },
    ],
    edges: [
      { id: 'e1', from: 'n1', fromPort: 'b', to: 'n2', toPort: 't',
        zh: '下一步', en: 'Next', router: 'smooth', style: 'solid',
        arrow: 'end', tone: 'slate' },
    ],
  },
]
```

Rules the validator enforces:

1. Exactly six entries, `key`s in this frozen order:
   `flowchart`, `architecture`, `journey`, `swimlane`, `orgchart`, `incident`.
2. Node `id`s are unique inside one template; edge `from` / `to` resolve to a node id in
   the same template.
3. `type` is in `NODE_TYPES`; `tone` is optional but if present is in `TONES`;
   `router` / `style` / `arrow` likewise if present.
4. `w` / `h` may be omitted (defaults per type). `x` / `y` are required and ≥ 0.
5. Every node has non-empty `zh` and non-empty `en`. Every edge label, when present at
   all, has both.
6. No two non-`band` nodes overlap by more than 12 px on either axis.
7. Each template has 8–24 nodes and 6–24 edges.
8. `band` nodes must be wide enough to contain the nodes they group.

Layout guidance: origin at `(40, 40)`; column pitch 200, row pitch 120; bands start at
`x: 24` and leave a `132px` left gutter for their own title, so grouped content sits at
`x ≥ 180`.

Template meaning (all six are required):

| key | product meaning |
| --- | --- |
| `flowchart` | Leave-approval flow: terminator → steps → decision → two outcomes |
| `architecture` | Layered web application: client / gateway / services / data bands |
| `journey` | User-journey map: 5 stage columns × 4 rows (`band` per row) |
| `swimlane` | Support-ticket flow across customer / agent / system lanes |
| `orgchart` | Product-team org chart, root and two levels |
| `incident` | Incident-response runbook with a decision and annotation notes |

Localized template titles and descriptions are **UI keys owned by the Lead**, in the
locale dictionaries inside `client.js`, named `template.<key>.title` and
`template.<key>.desc`. The template file itself carries no title strings.

## 7. UI contract (Lead owns the implementation; verifier asserts behaviour)

Panel regions, top to bottom:

1. **Header** — glyph, `panel.title`, `panel.subtitle`, then actions:
   `Templates`, `Export`, `Undo`, `Redo`, `Fit`, `+ board`.
2. **Board tab bar** — one tab per board, active tab marked `aria-selected="true"`;
   a rename input bound to the active board, and a delete button for it.
3. **Body** — left palette (one button per `NODE_TYPES` entry), centre canvas,
   right inspector shown only while something is selected.

Canvas interactions:

- Drag a node body to move it; the move is committed as one undo step on pointer-up.
- Adding from the palette places the shape in the first free spot near the view centre, so
  repeated clicks cascade instead of stacking on one another.
- A selected node shows eight resize grips. Dragging one resizes against the opposite
  edge, with a 24 × 16 minimum, snapped to the 4px grid and recorded as one undo step.
- Drag from a node's port handle to another node to create a connector; the nearest port
  pair on the target is chosen automatically.
- Click a node or connector to select it; click empty canvas to clear the selection.
- Drag empty canvas to pan; wheel zooms about the pointer; `Fit` re-centres the board.
- Double-click a node opens an inline text editor; `Enter` commits, `Shift+Enter` adds a
  line, `Esc` cancels without writing.
- `Delete` / `Backspace` removes the selection while no text editor is open.
- `Ctrl/Cmd+Z` undoes, `Ctrl/Cmd+Shift+Z` redoes; history holds up to 50 snapshots.

Inspector content per selection: text, tone swatches (for nodes) or label / router /
style / arrow (for connectors), and a delete action.

Persistence: the whole document is written to `localStorage[STORAGE_KEY]` on every
committed change and read once on mount. A `localStorage` that throws must leave the
panel fully working in memory.

Export: `JSON` (full document, download), `SVG` (true vector of the active board,
download), `Markdown` (board title, nodes grouped by type with their text, then a
connector list) — plus a copy-to-clipboard action for the Markdown. Downloads use the
`flowboard-` prefix and a toast confirms each one.

Boot state: when storage is empty, the document starts with one board built from the
`flowchart` template, named `template.flowchart.title`.

## 8. React surface available to the Client half (frozen)

The verifier drives the module through a hand-rolled hook runtime, so the Client half may
use **only** `React.createElement`, `React.useState`, `React.useEffect` and
`React.useRef`. No `useMemo`, `useCallback`, `useLayoutEffect`, `useId`,
`useSyncExternalStore`, context, portals, refs-as-props or class components.

Services are reached through `ctx.slots`, `ctx.locale`, `ctx.effect` only. The module
returns `{ inject: ['slots', 'locale'], apply(ctx) {} }`. Locale dictionaries are
registered with the two-argument `ctx.locale.register(NS, DICT)` form used by the sibling
plugins in this profile, and the panel re-renders on `ctx.locale.subscribe`.
